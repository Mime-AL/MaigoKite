# MaigoKite 产品愿景

> 状态：当前有效。本文定义产品边界；功能是否已经交付以 [交付路线](Roadmap.md) 和测试结果为准。

## 一句话定义

MaigoKite 是一个本地优先、可恢复、受用户控制的个人通用型智能体：用户描述目标，智能体可以在浏览器、工作区文件和外部工具之间持续执行，并在高风险动作前请求批准。

产品方向为一个人通过自己的电脑和手机使用同一个智能体。电脑持有执行环境与数据，手机作为远程任务和审批入口；手机远程访问尚未实现，首版范围见 [手机远程访问](../design/RemoteAccess.md)。

它不是编码专用智能体，也不是某个垂直行业软件。编码、资料研究、内容生产、设备辅助、招聘自动化等是建立在同一运行内核上的工作流。任何单一示例都不能决定核心架构。

## 首要问题

现有聊天产品擅长“给答案”，但用户真正完成工作仍要手动切换页面、复制信息、调用工具、记住进度并处理失败。MaigoKite 首先解决执行闭环：

1. 从自然语言目标形成可观察的工具步骤；
2. 在浏览器、文件和 MCP 工具间编排；
3. 用户离开界面后任务仍有独立生命周期；
4. 断线或进程重启后能解释任务处于何种状态；
5. 写入、提交和外部副作用由统一权限策略控制；
6. 通过本地技能和 MCP 扩展领域能力，不修改运行内核。

## 核心产品能力

| 能力 | 产品承诺 | 非目标 |
|---|---|---|
| 浏览器操作 | 打开公开网页、读取快照、填写、点击、按键和截图；动作进入权限与审计链路 | 无限制爬虫、绕过登录或站点安全机制 |
| 工具编排 | 模型可连续调用原生工具、技能和 MCP 工具，并把过程与最终回复分开展示 | 把模型思考 JSON 塞进回复框 |
| 持续任务 | HTTP 请求只负责启动任务，任务有独立 ID、状态、取消入口和事件时间线 | 将一个长 HTTP 请求伪装成任务系统 |
| 权限批准 | 仅查看 / 工作区内修改 / 显式完全访问；边界和人工审批分离，支持窄范围复用 | 逐工具风险配置、默认依赖额外审核 Agent；精确模式值见工具权限文档 |
| 状态恢复 | 消息、任务、审批和事件落盘；断线可重放；无安全检查点的重启任务明确标记 interrupted | 在无法安全恢复时假装自动续跑 |
| 技能 / MCP | 本地声明式技能提供可审阅流程知识；MCP 提供进程外工具协议 | 默认执行来源不明的技能代码 |
| 手机远程访问（规划中） | 在手机发起主机任务、查看进度、批准操作与阅读结果；断线后恢复查看 | 手机运行第二套智能体、复制执行数据库或承诺主机关机后继续执行 |

## 产品边界

### 内核负责

- 会话、任务、工具调用、审批、事件和审计的权威状态；
- 模型适配和模型提供方-neutral 工具 Calling；
- 浏览器与工作区资源边界；
- 技能发现、MCP 连接和统一 ToolPolicy；
- Web/Electron 客户端所需的 REST 和事件协议。

### 个人流程与扩展负责

- 行业术语、步骤模板、表单规则和外部系统连接；
- 生图、电子开发、业余无线电、求职等领域流程；
- 可替换的模型、搜索服务、MCP Server 和技能包。

### 当前不作为核心卖点

- “对话自动总结成技能”：可以是效率功能，但市场上已有大量同类实现；
- 特定设备刷机、日志管理或单一网站自动化：只能作为经验证的领域包；
- 多智能体数量、向量库、DSL 或技术栈本身：它们是实现手段，不是用户价值。

## 差异化原则

差异化不来自再造一个聊天框，而来自“可控的持续执行”：

- 同一任务跨网页、文件和工具保持状态；
- 用户随时能看到做了什么、在等什么、可以停止什么；
- 重连后客户端从持久化事件恢复，而不是依赖内存 WebSocket；
- 所有扩展复用同一批准、审计和恢复语义；
- 本地部署和本地模型是一等路径，同时允许用户配置兼容 API。

## 目标用户

目标用户是愿意把重复数字工作交给智能体、同时要求过程可见和副作用可控的个人。开发者是重要用户，但不是唯一用户。个人工作区用于组织项目与资料，多个个人设备连接同一个主体。团队成员、角色与共享治理不进入当前产品路线。现有工作区和主体 ID 保留兼容，决策见 ADR-024。

## 设计原则

1. **运行内核先于领域功能**：六项核心能力未闭环前，不扩张垂直页面。
2. **权威状态唯一**：Python 核心服务管理业务事实与资源，新路径执行状态由 LangGraph 检查点承担；FastAPI 在同进程承担协议与访问边界。
3. **事件可重放**：实时事件是持久化任务日志的投影，不是唯一事实来源。
4. **诚实恢复**：只有存在已验证检查点时才自动继续，否则标记 interrupted 并让用户重试。
5. **能力统一治理**：原生工具、浏览器、技能和 MCP 使用同一注册、校验、权限、审计接口。
6. **界面只展示真实能力**：可以提前注册规划页面，但必须清晰标记未实现，不能用空表单伪装功能。
7. **渐进复杂度**：默认模式能直接使用；远程访问显式启用，高级路由与工作流按需出现。

## 成功标准

首个可用版本以端到端任务而非页面数量衡量。用户能发起需要网页读取和工具操作的任务，离开并重新打开界面后看到完整进度。用户能批准或拒绝风险动作，必要时停止任务，并通过技能/MCP 加入新能力而不修改内核。
