# NanamiGopher 产品愿景

> 状态：Current。本文定义产品边界；功能是否已经交付以 `Milestones.md` 和测试结果为准。

## 一句话定义

NanamiGopher 是一个本地优先、可恢复、受用户控制的通用型 Agent：用户描述目标，Agent 可以在浏览器、工作区文件和外部工具之间持续执行，并在高风险动作前请求批准。

它不是编码专用 Agent，也不是某个垂直行业软件。编码、资料研究、内容生产、设备辅助、招聘自动化等是建立在同一运行内核上的工作流；任何单一示例都不能反向绑架核心架构。

## 首要问题

现有聊天产品擅长“给答案”，但用户真正完成工作仍要手动切换页面、复制信息、调用工具、记住进度并处理失败。NanamiGopher 首先解决执行闭环：

1. 从自然语言目标形成可观察的工具步骤；
2. 在浏览器、文件和 MCP 工具间编排；
3. 用户离开界面后任务仍有独立生命周期；
4. 断线或进程重启后能解释任务处于何种状态；
5. 写入、提交和外部副作用由统一权限策略控制；
6. 通过本地 Skill 和 MCP 扩展领域能力，不修改运行内核。

## 核心产品能力

| 能力 | 产品承诺 | 非目标 |
|---|---|---|
| 浏览器操作 | 打开公开网页、读取快照、填写、点击、按键和截图；动作进入权限与审计链路 | 无限制爬虫、绕过登录或站点安全机制 |
| 工具编排 | 模型可连续调用原生 Tool、Skill 和 MCP Tool，并把过程与最终回复分开展示 | 把模型思考 JSON 塞进回复框 |
| 持续任务 | HTTP 请求只负责启动任务，任务有独立 ID、状态、取消入口和事件时间线 | 将一个长 HTTP 请求伪装成任务系统 |
| 权限批准 | read_only / workspace / full_access 三种模式；风险动作按资源范围批准 | 用繁琐的逐工具参数替代可理解的模式 |
| 状态恢复 | 消息、任务、审批和事件落盘；断线可重放；无安全检查点的重启任务明确标记 interrupted | 在无法安全恢复时假装自动续跑 |
| Skill / MCP | 本地声明式 Skill 提供可审阅流程知识；MCP 提供进程外工具协议 | 默认执行来源不明的 Skill 代码 |

## 产品边界

### 内核负责

- 会话、任务、工具调用、审批、事件和审计的权威状态；
- 模型适配和 Provider-neutral Tool Calling；
- 浏览器与工作区资源边界；
- Skill 发现、MCP 连接和统一 ToolPolicy；
- Web/Electron 客户端所需的 REST、gRPC 和事件协议。

### 扩展负责

- 行业术语、步骤模板、表单规则和外部系统连接；
- 生图、电子开发、业余无线电、求职等领域流程；
- 可替换的模型、搜索服务、MCP Server 和 Skill 包。

### 当前不作为核心卖点

- “对话自动总结成 Skill”：可以是效率功能，但市场上已有大量同类实现；
- 特定设备刷机、日志管理或单一网站自动化：只能作为经验证的领域包；
- 多 Agent 数量、向量库、DSL 或技术栈本身：它们是实现手段，不是用户价值。

## 差异化原则

差异化不来自再造一个聊天框，而来自“可控的持续执行”：

- 同一任务跨网页、文件和工具保持状态；
- 用户随时能看到做了什么、在等什么、可以停止什么；
- 重连后客户端从持久化事件恢复，而不是依赖内存 WebSocket；
- 所有扩展复用同一批准、审计和恢复语义；
- 本地部署和本地模型是一等路径，同时允许用户配置兼容 API。

## 目标用户

首批目标用户是愿意把重复数字工作交给 Agent、同时要求过程可见和副作用可控的个人用户与小团队。开发者是重要用户，但不是唯一用户。团队能力复用同一代码和 Workspace 隔离模型，不拆成两套产品。

## 设计原则

1. **运行内核先于领域功能**：六项核心能力未闭环前，不扩张垂直页面。
2. **权威状态唯一**：Python Agent Core 拥有任务、审批和执行状态；Go Gateway 只负责边缘协议与安全边界。
3. **事件可重放**：实时事件是持久化任务日志的投影，不是唯一事实来源。
4. **诚实恢复**：只有存在已验证检查点时才自动继续，否则标记 interrupted 并让用户重试。
5. **能力统一治理**：原生 Tool、浏览器、Skill 和 MCP 使用同一注册、校验、权限、审计接口。
6. **界面只展示真实能力**：可以提前注册规划页面，但必须清晰标记未实现，不能用空表单伪装功能。
7. **渐进复杂度**：默认模式能直接使用；高级路由、工作流和团队治理按需出现。

## 成功标准

首个可用版本不以页面数量衡量，而以端到端任务衡量：用户能发起一个需要网页读取和工具操作的任务，离开并重新打开界面后看到完整进度，对风险动作批准或拒绝，必要时停止任务，并能通过 Skill/MCP 加入新能力而不改内核。
