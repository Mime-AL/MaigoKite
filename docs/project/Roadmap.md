# NanamiGopher 路线图

> 状态：Current。阶段按能力依赖排序，不再使用缺乏依据的固定周数承诺。

## 排序规则

路线图的最小交付单元是可验收的端到端闭环，而不是页面或数据表。一个能力只有在 Core、权限、持久化、API、界面和测试同时连通后才算交付。

```
通用执行内核 → 日常可用性 → 可组合工作流 → 团队与生态
```

## Phase 1：通用 Agent 执行内核

目标：用户可安全启动、观察、恢复和停止一个跨工具任务。

### 必须闭环

- 多模型配置、会话级模型选择和 Provider-neutral Tool Calling；
- 原生工具注册、参数校验、连续工具调用与结构化结果；
- Playwright 浏览器操作：open / snapshot / fill / click / press / screenshot / close；
- 独立任务生命周期：task ID、状态、取消、持久化事件序列；
- 重连恢复：客户端读取事件历史并与实时流去重；
- 重启恢复：waiting_approval 保持可决策；无安全检查点任务标记 interrupted；
- read_only / workspace / full_access 权限模式、风险分级、审批和审计；
- 本地声明式 Skill 发现/读取，以及配置式 stdio MCP 发现/调用；
- Web/Electron 基础客户端：对话、过程面板、停止按钮、审批卡片、扩展清单；
- 工作区文件读取、预览与 Git Diff（作为通用文件能力，不定义产品方向）。

### 验收场景

1. Agent 打开网页、读取内容，并在点击或填写等副作用动作前按策略批准；
2. 同一模型轮次可连续调用多个 Tool，失败显示可执行提示，最终回复不泄漏工具 JSON；
3. 切换对话不阻断其他任务，重进对话能恢复任务状态和活动时间线；
4. 用户点击停止后，任务、待审批和运行中 Tool 进入取消语义；
5. 新增 `skills/<name>/SKILL.md` 或配置 MCP Server 后，能力出现在统一目录并受 ToolPolicy 管理。

### 明确不进入 Phase 1

- 自动长期记忆、Embedding、向量索引；
- 生图/OCR 等专用模型注册；
- DSL 可视化编排、多 Agent、Skill 市场；
- 特定行业工作台。

这些功能不是被删除，而是不能先于运行内核占用主线。

## Phase 2：日常可用性与可靠性

目标：让核心内核能稳定承担个人日常任务。

- 安全检查点和可重试步骤，使部分任务可在重启后自动继续；
- 浏览器会话隔离、下载/上传策略、登录态的显式用户托管；
- 并行任务队列、限流、超时、退避和资源配额；
- 模型能力目录、按能力路由和显式 fallback；
- 可搜索的会话/任务历史、通知和后台任务入口；
- Skill 热重载、校验结果和启用/禁用；MCP 健康检查与重启；
- 结构化错误码、延迟与 Token 等最小运行指标；
- Memory v1：用户可见、可编辑、可关闭的事实/偏好注入；
- Embedding/索引只在有真实检索场景后实现；
- 生图、OCR 等作为 Tool Provider 接入，不进入 Chat Model 配置。

## Phase 3：可组合工作流与领域包

目标：把验证过的任务沉淀为可复用流程，而不污染内核。

- Workflow 定义、条件、重试、人工节点和版本化检查点；
- 从成功任务生成候选工作流，由用户审阅后保存；
- Skill 包版本、内容 hash、签名、安装、回滚和 Workspace Grant；
- MCP 多传输与凭证引用治理；
- 子任务/子 Agent，仅在并行拆分带来可测收益时引入；
- 领域包试验：研究、内容、设备辅助、开发、招聘等按需求证据排序；
- 每个领域包必须定义目标用户、频率、失败成本和人工接管点。

## Phase 4：团队与生态

目标：在单机内核成熟后扩展到多人和第三方生态。

- 服务器身份认证、团队 Workspace、角色与共享资源；
- PostgreSQL 等服务端存储适配和正式迁移体系；
- 多实例任务租约、队列和事件分发；
- Skill/MCP 管理后台、供应链审核和市场；
- 跨设备通知、运营审计、备份与灾难恢复；
- 安全、性能和兼容性基准成为发布门禁。

## 依赖关系

| 后续能力 | 必须依赖 |
|---|---|
| 自动恢复 | 持久任务、事件日志、安全检查点、幂等 Tool |
| Memory 自动注入 | 明确数据边界、用户控制、检索评测 |
| 多 Agent | 单 Agent 任务生命周期、取消、预算和事件模型稳定 |
| Skill 市场 | 本地 Skill 契约、签名/哈希、授权和回滚稳定 |
| 团队模式 | 身份认证、Workspace 隔离、服务端数据库迁移 |

## 当前推进原则

- 优先修复 Phase 1 六项能力中的断链，不用 Phase 2 页面数量掩盖缺口；
- 可以提前注册后续页面，但必须显示“规划中”且不能保存无后端语义的设置；
- 文档示例不得硬编码具体模型、价格、速度或服务端生成参数；模型服务端参数由 Provider/服务端负责，Agent 只保存连接、模型标识和必要的任务偏好；
- 每轮交付后更新 `Milestones.md` 的真实状态，并以自动化测试和可重复冒烟作为证据。
