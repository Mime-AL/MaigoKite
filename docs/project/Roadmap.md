# NanamiGopher 交付路线与状态

> 状态：当前有效（计划与证据分开）。
> 整理日期：2026-10-09。原阶段完成度表核验于 2026-09-18，本轮未重新运行全量回归。
> 范围：交付顺序、实现证据、缺口及发布门禁。需求只在 [需求与验收](../requirements/RequirementList.md) 定义。

## 1. 排序原则

最小交付单元是可验收的端到端任务，不是页面、数据表或包数量。优先复用成熟实现，把开发投入放在个人任务体验、权限交互、工作区和桌面交付。

```text
通用执行闭环 → 日常可靠性与手机远程 → 经验证的个人工作流 → 扩展分发与多设备体验
```

团队成员、角色管理、PostgreSQL 团队部署、分布式执行和多人协作不进入当前路线。保留既有工作区/主体字段兼容，不因精简文档删除业务数据边界。

### 新运行时迁移

普通聊天显式启用 LangGraph 后，现有注册工具已通过公开转换接线，包括文件、搜索、命令、联网、浏览器、技能与已连接 MCP。新增接线尚未验收，不能用旧测试结果覆盖。原生 HITL 保留完整工具批次、逐项呈现审批；文件写入有内容相等时的状态核对。代码与测试入口见 [智能体运行时设计](../design/AgentRuntime.md)。

默认仍是 legacy。浏览器与 MCP 工具已新增接线，但 stdio 协议客户端未替换；显式 `/tool` 仍走旧路径。真实模型提供方、恢复、副作用与取消回归是切默认门禁，启用和删除旧路径的条件只在 [运行时迁移说明](../development/RuntimeMigration.md) 维护。

### 核心发布阻塞

1. 完整事件分页与连续游标，覆盖超过 1000 条历史以及补拉期间的新事件。
2. 浏览器资源隔离、超时回收、下载上传与整链路 E2E。
3. 取消必须等待实际清理；legacy/MCP/同步线程限制不得被新运行时的结果掩盖。
4. 检查点、产品投影和审批审计的边界，以及文件副作用 crash/replay 回归。
5. 网关 + 核心服务 + WebSocket + 浏览器整链路及桌面安装包验收。

状态恢复不等于任意步骤自动续跑；源码构建不等于安装包可用。

## 3. 日常可靠性与手机远程

目标是让现有内核稳定承担个人任务，先解决上述缺口，再开放能力。

手机远程为 P1、规划中，尚无设备配对或移动客户端。按 [手机远程访问](../design/RemoteAccess.md) 的 R0–R3 推进：可靠性 → 私有连接与配对 → 手机任务/审批 → 真机断线恢复。不另开运行时选型，不以记忆、工作流或团队系统为前置条件。

其他候选按依赖和实际需求推进：

- 安全续跑、受控重试、并发预算和超时。
- 登录态托管、历史检索、后台任务与必要通知。
- 扩展健康管理和热重载。
- 可编辑、可关闭的用户记忆注入；目前只有手动 CRUD。
- 模型能力/路由/降级；向量嵌入、生图/OCR 必须有真实使用场景及完整 API/执行闭环。

## 4. 个人工作流与扩展生态

| 候选 | 准入条件 |
|---|---|
| 复用成功任务 | 先用声明式技能；确有确定性暂停/恢复需求才组合现有 LangGraph 状态/检查点 |
| 子任务/子智能体 | 单智能体基线证明并行收益，隔离、预算、取消和汇总明确 |
| 技能包管理、可信分发 | 用户有实际安装/更新需求，再确定版本、摘要值、签名、权限预览和回滚 |
| MCP 多传输 | 先明确认证、凭证与网络信任边界 |
| 研究、内容、设备辅助、开发、招聘等 | 需求频率、失败成本、节省时间和人工接管证据 |
| 原生手机 App、系统推送、低配置连接 | 首版远程使用反馈后确定 |
| 数据导出、备份和可携带性 | 明确格式、一致性和恢复演练 |

这些是候选方向，不是要求同时建设的平台清单。不会为此预设自研工作流引擎、插件框架、事件溯源或分布式调度。
