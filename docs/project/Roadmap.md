# MaigoKite 交付路线与状态

> 状态：当前有效（计划与证据分开）。
> 整理日期：2026-10-10。前四批已完成获准的定向后端收口；未运行全量发布回归。
> 范围：交付顺序、实现证据、缺口及发布门禁。需求只在 [需求与验收](../requirements/RequirementList.md) 定义。

## 1. 排序原则

最小交付单元是可验收的端到端任务，不是页面、数据表或包数量。优先复用成熟实现，把开发投入放在个人任务体验、权限交互、工作区和桌面交付。

```text
通用执行闭环 → 日常可靠性与手机远程 → 经验证的个人工作流 → 扩展分发与多设备体验
```

团队成员、角色管理、PostgreSQL 团队部署、分布式执行和多人协作不进入当前路线。保留既有工作区/主体字段兼容，不因精简文档删除业务数据边界。

- 浏览器使用原 Playwright context 与 asyncio 锁：默认最多 4 个会话（含启动中），30 分钟无工具操作后回收；忙页面跳过回收。等待页面锁时取消不关闭页面，持锁操作取消/超时才关闭自己上下文。登录配置数据保留；完全访问下载的最终路径复查沿用同一边界。

### 核心发布阻塞

2026-10-11 查漏补缺（源码接入，不记作运行验收）：

- 聊天：移除快照缓冲与延后消息投影的提前确认；单回合投影失败回滚，去重身份/水位后提交；错误明确提示并重连。此前前端测试通过记录不覆盖此次修改，聊天可靠性仍待定向故障注入验收。
- 扩展：新配置的 Skill 扫描/MCP 连接不完整时拒绝提交；旧连接停用即更新状态；普通聊天、回答、恢复入口同样准备上次生效配置的 MCP 凭证。缺失凭证明确报错，不把部分目录当成成功应用。
- 子 Agent：模型调用前重查撤销，子任务自己的原生 TaskGroup 在失败/超时后等待读工具清理；不扩大为写入子 Agent 或后台委派。
- 活跃进程：GUI 接实时输出/停止；新增受审批的标准输入与 EOF，Go/Python gRPC 绑定同步生成。保留短命令超时，不是终端/后台调度。
- 浏览器：官方持久配置支持独立窗口登录；session 绑定对话/工作区；新增受审批的文件上传、下载，路径边界和无覆盖写入。没有新增浏览器协议或自动登录凭证框架。

本轮仅进行静态检查与接口编译，未运行 Python/Vitest/E2E 或真实网站/模型测试。需要实际验收的分支为：投影异常后重放、快照并发、重启 MCP 凭证/重载失败、子任务取消/撤销、进程输入/退出竞争、登录重启及上传下载取消。第五批不能据此标记为发布完成。

静态回执：`vue-tsc --noEmit --incremental false`、本轮五个前端逻辑/组件文件 ESLint、九个 Python 修改文件的 `ruff --select F --no-cache`、BrowserRuntime/ProcessRegistry 两文件的 mypy（跳过依赖检查），以及 Gateway `go build ./internal/api ./internal/grpc` 均通过。生成 gRPC 绑定所用的编译器和检查缓存均限定在本轮临时目录，结束后清理；没有使用旧测试通过数给本轮背书。

扩展管理本次补的是第五批的产品入口，不重新打开前四批 Runtime 重构：复用官方 MCP SDK、既有 SkillRegistry、workspace_settings、凭证服务与 owner 权限。期望配置与生效配置分开，重启不自动应用待生效编辑；有任务或待处理审批/提问时拒绝应用新配置，恢复原 MCP 连接可保留待审批/待回答任务，但仍要求没有活动运行。

此前扩展管理批次补齐三处源码缺口：批准 MCP 前从密钥链恢复原连接，失败不消费审批；候选 Runtime 打开后才切换，准备失败保留原聊天入口（已断开 MCP 需另行恢复）；Skill 扫描使用标准库工作线程、扫描预算和协作式停止。该批次未新增插件平台，仅做源码检查；上方 2026-10-11 回执说明此次追加修复与静态检查。此前定向后端通过结论不外推到新增代码，发布前仍需覆盖重启审批、应用失败/断线/关闭、扫描超限和 GUI 交互。

1. GUI 的真实快照/断线交互验收；后端注册屏障、事件身份、超过 1000 条历史及追加补拉已经定向通过，不再列成未实现的基础设施。
2. 浏览器资源隔离、超时回收、下载上传与整链路 E2E。
3. 不把已通过的本地取消/关闭扩大为远端 MCP 副作用停止或 Windows 进程树回收承诺。
4. 发布时演练产品库与 checkpoint 一起备份/恢复；审批和文件副作用 crash/replay 已定向通过，任意工具恢复仍不开放。
5. 网关 + 核心服务 + WebSocket + 浏览器整链路及桌面安装包验收。

状态恢复不等于任意步骤自动续跑；源码构建不等于安装包可用。

### 第三批的上下文、缓存与 token 策略

## 3. 日常可靠性与手机远程

目标是让现有内核稳定承担个人任务，先解决上述缺口，再开放能力。

手机远程为 P1、规划中，尚无设备配对或移动客户端。按 [手机远程访问](../design/RemoteAccess.md) 的 R0–R3 推进：可靠性 → 私有连接与配对 → 手机任务/审批 → 真机断线恢复。不另开运行时选型，不以记忆、工作流或团队系统为前置条件。

其他候选按依赖和实际需求推进：

- 安全续跑、受控重试、并发预算和超时。
- 登录态托管、历史检索、后台任务与必要通知。
- 扩展健康管理和热重载。
- 可编辑、可关闭的用户记忆注入；目前只有手动 CRUD。
- 模型能力/路由/降级；向量嵌入、生图/OCR 必须有真实使用场景及完整 API/执行闭环。

个人工作流与受控子 Agent 保留为产品发展方向；清理空骨架不取消需求。表中准入条件决定交付顺序和实现规模，不要求同时建设一套平台。不会为此预设自研工作流引擎、插件框架、事件溯源或分布式调度。
