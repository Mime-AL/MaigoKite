# 工具权限与执行安全

> **状态**：当前有效
> **架构版本**：v1
> **源码更新**：2026-10-11（本批只做静态检查，未运行测试或 GUI 联调）
> **权威范围**：工具风险等级、权限模式、审批与 hard-deny

系统级认证、凭证与网络安全见 [安全边界](../../ops-security/Security.md)。

## 1. 分层

```text
Go AccessPolicy                  Python ToolPolicy
谁能访问哪个 Workspace 资源       Agent 能否执行具体能力与参数
```

两层都必须通过。网关的允许结果不能替代 ToolPolicy。

## 2. 风险等级

| 等级 | 含义 | 基础示例 |
|---|---|---|
| L1 | 无副作用读取 | 工作区内读取、glob、grep |
| L2 | 可恢复的低风险状态修改 | todo、短时等待、本地临时状态 |
| L3 | 外部交互或受限命令 | web search/fetch、受限 shell |
| L4 | 持久化写入 | 工作区文件写入、批量编辑 |
| L5 | 重大或难以恢复的影响 | 大范围删除、发布、发送外部消息、系统变更 |

等级是基础风险，不是最终决定。参数、路径、数据敏感度和部署策略可以提升等级或触发 hard deny。

## 3. 权限模式

| 用户档位 | 自动执行 | 请求批准 |
|---|---|---|
| 只读 `read_only` | 工作区内无副作用读取与搜索 | 编辑、命令、联网及其他副作用操作 |
| 工作区内修改 `workspace`（默认） | 工作区读取、低风险状态、文件编辑、真实沙箱内的普通命令 | 越界、命令联网、显式升级和敏感操作 |
| 完全访问 `danger_full_access` | 已启用工具直接执行，命令不使用工作区沙箱；不因 L5 逐项询问 | 不进行权限审批；仍受工具禁用、显式部署限制和操作系统权限约束 |

说明：

- `workspace` 的普通命令不再靠解释器白名单实现隔离。复用 bubblewrap 限定文件系统与网络，显式删除、修改权限等命令仍要求批准。命令识别不是完整的副作用分析，不能识别脚本中所有破坏行为。
- `danger_full_access` 必须通过新的明确模式值选择，不等于取得管理员权限，不启用原本停用的工具，也不取消工具本身的参数、会话归属、超时等约束。
- 旧 `full_access / auto` 统一解释为兼容值 `workspace_auto`：保留工作区边界及旧 L1–L4 自动范围，L5 仍需批准。启动时规范化历史会话，旧设置/YAML/客户端请求同样不会升级成无限制权限。前端须将兼容值显示为“旧版受限自动”，不能再标为“完全访问”。
- 窄授权不覆盖 L5；完全访问是单独、显式的执行模式，而不是永久 L5 授权记录。
- L1–L5 是服务端风险模型，不作为普通用户需要逐工具调节的设置项。

个人版权限配置只有 `default_mode`，会话使用自己的 `permission_mode`。后端不再保存或传递逐工具可调风险矩阵，也没有独立的内存 grant/scope 权限存储。历史数据库中的 `tool_levels` 被忽略，下次保存该设置时清除；已有风险标签和审批审计保留。

`read_only` 允许用户对具体写入批准，搜索子进程使用只读工作区挂载。是否启用工具和是否允许调用仍是独立边界。没有独立审核模型，不注册“帮我批准”，也不增加调用模型判断风险的隐性成本。借鉴 [DSH 基础预设](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/interaction/permission-presets/src/index.ts) 的沙箱/审批分离，不移植其插件框架或实验 Auto review。

## 4. 基础工具映射

| 工具能力 | 基础等级 | 动态规则 |
|---|---|---|
| file_read/glob/grep | L1 | 敏感或范围外路径升级/拒绝 |
| todo_write/sleep | L2 | 超额资源占用可拒绝 |
| web_search/web_fetch | L3 | 携带敏感凭证或禁止域名时拒绝 |
| bash | L3 | 按命令、目录和副作用提升至 L4/L5/hard deny |
| file_write/file_edit | L4 | 工作区外需要精确参数审批；完全访问无需审批 |
| external_send/publish | L5 | 必须展示接收方和内容预览 |

技能声明的是 capability 请求。最终等级由受信 ToolPolicy 根据能力和参数决定。未知能力默认拒绝。

## 5. 决策输入与结果

```text
Gateway：验证主体能访问工作区
ToolRegistry：工具存在且当前启用，校验 schema
PermissionManager.evaluate(tool_name, arguments, approved, risk_override, mode)
    → allow | approval_required | deny
```

顺序：

1. Schema 校验并规范化参数。
2. 解析实际资源范围和副作用。
3. 检查工作区访问与能力授权。
4. 检查 hard-deny。
5. 计算有效风险等级。
6. 应用模式与已验证的一次性审批。`risk_override` 只来自受信工具/MCP 注册元数据，不来自客户端或工作区设置。
7. 校验可复用审批回执，生成仅由服务端持有的 `sandbox_mode / allow_network` 执行快照；不新增 Grant 表或权限框架。
8. 执行或创建审批。

## 6. 硬禁止

所有模式都拒绝未启用/未知工具、不合法参数、违反显式部署 allowlist 或 blocked_patterns 的调用。普通模式额外拒绝已识别的凭证路径、直接写入 `.git` 元数据及少量明显破坏系统的命令；单次人工批准不能覆盖这些拒绝。完全访问不保留这套工作区保护，否则名称会与行为不符。

受限命令通过 `sandbox_permissions=require_escalated` 请求单次沙箱外执行，或通过 `network_access=true` 仅请求网络；参数只是请求，不是授权。普通模式下都必须审批。Git 元数据在沙箱内只读，修改 Git 必须先提出明确升级请求。已明确禁用的操作仍不能借升级绕过。

当前宿主命令没有独立网络隔离后端，所以单次沙箱外命令还必须明确包含 `network_access=true` 并一起批准，否则不启动。只有 `network_access=true` 不会解除工作区文件隔离。完全访问模式已经显式包含宿主网络许可。越界 glob/grep 在批准后仍把目标目录放入只读、断网沙箱，不借批准获得任意宿主命令权限。

已知路径与命令规则只是确定性保护，不是完整敏感数据检测/DLP。任意代码在允许目录内的副作用不能只靠字符串匹配可靠识别。

## 7. 审批

审批必须绑定：

```text
principal_id
workspace_id
task_id
tool_call_id
capability
normalized_arguments_hash
resource_scope
risk_level
expires_at
version
```

- 参数或范围变化后审批失效。
- 每份具体调用审批只能消费一次；可选窄授权回执见下文。
- 过期、拒绝和重复提交必须有确定结果。
- UI 显示能力、目标、参数摘要、副作用、凭证与网络范围。
- 审批与任务/工具调用状态在同一事务中更新。
- 决定只接受仍等待审批的任务，不能用遗留 pending 记录重新激活已结束任务。
- `allow` 恢复可能调用模型，先准备凭证，再消费审批；LangGraph 路径继续使用原生 HITL 恢复。
- `deny` 结束当前回合，不调用模型、不读取密钥链，不需要可初始化的模型配置。新路径先等待上一 interrupt 根任务退出；拒绝、审计、剩余未执行调用/待审批项的关闭同事务提交，再发布终态。
- 拒绝后的检查点不恢复执行，不伪造已执行的工具结果；它仍可保留作诊断记录。下一回合只导入可见产品历史。

### 窄范围复用

- 决定接口支持 `scope=once|task|session`，默认 `once`。客户端只能选择服务端 `allowed_scopes` 中的值，不能提交自定义授权规则。
- 复用范围由策略生成：文件写入/编辑分别绑定同一父目录（不含子目录）；命令绑定完全一致的 argv、工作目录；网页读取/打开绑定 origin；搜索绑定服务提供方。
- 同时绑定主体、工作区、会话、模式和策略版本；L5、MCP、不透明外部操作和沙箱外命令不提供复用。
- `task` 限当前活跃任务；`session` 限当前会话。二者最多 8 小时，不是永久白名单，可通过授权撤销接口提前结束。
- 权限模式、目录、归档、工具选择及生效扩展变化撤销相关回执；每次工具调用重新查询，不依赖旧进程内存。只读子 Agent 不继承授权。
- 回执字段保存在现有 `approvals`；LangGraph checkpoint 仍是暂停/恢复的唯一执行事实来源。撤销影响后续调用，不撤销已开始的副作用或已批准的原始单次调用。

## 8. 沙箱与当前限制

- 内置工具使用路径、进程和网络策略限制。
- exec_command 不经过 shell 展开。Linux 复用 bubblewrap，只挂载只读运行库和指定工作区，受限命令默认不共享网络。搜索使用只读工作区；工作区根部已知凭证文件遮蔽，`.git` 只读。这不是递归敏感内容隔离。
- 受限进程沙箱不可用时返回 `SANDBOX_UNAVAILABLE`，不再回退为普通宿主命令。当前未实现 Windows/macOS 受限执行后端；不能假装这些平台已受保护。`file_read` 等进程内工具继续使用产品路径校验。
- 工作区仍不得配置为文件系统根目录。单次已批准的显式升级命令、以及 `danger_full_access` 模式使用宿主 argv 执行，仍保留输出限制、取消、超时和进程清理。
- 越界文件操作只有匹配审批/窄授权或显式完全访问才执行；浏览器文件操作同时校验页面 URL 和会话归属。完全访问不增加 Browser/MCP/子 Agent 的新功能。
- 第三方 MCP Server 默认按不受信代码处理。
- 本地技能只读取声明内容，不获得独立进程权限；目标 SkillGrant 尚未交付，当前 MCP 信任与环境来自部署配置。
- 子进程不继承完整宿主环境。
- 超时和取消应覆盖所属进程及后代，但当前 MCP 和同步线程存在限制；实际范围见 [智能体运行时设计](../../design/AgentRuntime.md)，不把目标要求当作已完成。

## 9. 审计

记录：

- 决策输入的安全摘要和最终结果。
- 风险升级原因与命中的 hard-deny 规则。
- 审批创建、决定、消费和过期。
- 工具开始、结束、失败、取消与资源范围。

不记录完整敏感凭证、认证头或未经脱敏的敏感内容。
