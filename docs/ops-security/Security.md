# NanamiGopher 安全架构

## 概述

NanamiGopher 采用纵深防御（Defense-in-Depth）策略，通过多层安全机制保障系统、数据和用户隐私的安全。本档描述整体安全架构、权限分级、过滤策略、沙箱设计及网络安全规范。

---

## 1. 安全分层模型

NanamiGopher 的安全架构由以下四层组成：

| 层级 | 机制 | 说明 |
|------|------|------|
| L0 输入过滤 | 正则 + 向量语义拦截 | 在进入任何处理管线前对原始输入进行清洗与拦截 |
| L1 权限控制 | L1-L5 分级授权 | 基于工具能力与风险等级动态审批 |
| L2 沙箱隔离 | LocalSandbox / DockerSandbox | 代码执行环境隔离，限制资源与文件系统访问 |
| L3 审计日志 | EventBus + 结构化日志 | 全链路追踪，支持事后审计与合规检查 |

四层独立生效，任意一层拦截即终止请求，不存在"一票放行"。

---

## 2. L1-L5 权限分级

权限分级以工具能力为基础，按风险从低到高分为五个级别。每个级别对应不同的审批策略与执行约束。

### 2.1 级别定义

| 级别 | 名称 | 风险描述 | 审批策略 |
|------|------|----------|----------|
| L1 | 只读查询 | 仅读取文件内容、搜索文本，不修改任何数据 | 自动放行 |
| L2 | 受限操作 | 读取系统信息、环境变量，不接触网络 | 自动放行 |
| L3 | 网络与命令 | 执行 shell 命令、发起网络请求 | 需显式确认 |
| L4 | 文件写入 | 创建、编辑、删除文件 | 需显式确认 + 路径白名单 |
| L5 | 高风险操作 | 生成图像、调用外部 API、修改系统配置 | 需管理员审批 |

### 2.2 工具权限映射

| 工具 | 权限级别 | 说明 |
|------|----------|------|
| `file_read` | L1 | 读取文件内容 |
| `glob` | L1 | 文件路径匹配 |
| `grep` | L1 | 文本搜索 |
| `bash` | L3 | 执行 shell 命令 |
| `web_search` | L3 | 发起网络搜索请求 |
| `file_write` | L4 | 创建/覆盖文件 |
| `file_edit` | L4 | 编辑已有文件 |
| `image_generate` | L5 | 调用图像生成服务 |

### 2.3 权限提升机制

- 权限不可跨级继承：L1 工具不自动获得 L3 能力。
- 权限提升需满足全部条件：
  1. 用户显式授权（UI 确认或配置文件声明）
  2. 当前 Task 的权限上下文已激活
  3. 输入过滤层未触发拦截

## 3. 白名单机制

白名单是权限控制的**降级因子**（Degradation Factor），而非一票放行。

### 3.1 工作原理

```
输入 → 安全过滤(L0) → 权限检查(L1) → 白名单匹配 → 沙箱执行(L2) → 审计记录(L3)
                    ↑                              ↓
                    └── 白名单未命中时回退到默认拒绝策略
```

### 3.2 降级特性

- 白名单仅降低审批门槛，不绕过输入过滤和沙箱隔离。
- 当白名单规则与权限分级冲突时，取更严格的一方。
- 白名单变更需经过配置审计日志记录。

### 3.3 白名单配置示例

```yaml
whitelist:
  trusted_paths:
    - "/workspace/**"
    - "/tmp/nanamigopher/**"
  trusted_commands:
    - "ls"
    - "cat"
    - "grep"
  trusted_domains:
    - "api.example.com"
```

## 4. 安全过滤策略

### 4.1 处理顺序

```
1. 截断处理：超长输入按最大 token 上限截断，避免缓冲区溢出
2. 正则拦截：匹配已知攻击模式（SQL 注入、XSS、命令注入等）
3. 向量语义拦截：基于嵌入模型判断输入语义是否越权
```

### 4.2 正则规则集

| 类别 | 示例模式 | 动作 |
|------|----------|------|
| SQL 注入 | `' OR 1=1`、`; DROP TABLE` | 拒绝 |
| XSS | `<script>`、`javascript:` | 拒绝 |
| 命令注入 | `&& rm -rf`、`; wget` | 拒绝 |
| 路径遍历 | `../etc/passwd`、`..\\..` | 拒绝 |

### 4.3 向量语义拦截

- 使用嵌入模型将输入转换为向量表示。
- 与预定义的恶意语义向量库进行相似度计算。
- 余弦相似度 > 0.85 时触发拦截。
- 向量库每周自动更新，增量训练来自已确认的攻击样本。

## 5. 沙箱设计

### 5.1 架构演进

| Phase | 沙箱类型 | 能力 | 上线计划 |
|-------|----------|------|----------|
| Phase 1 | LocalSandbox | 进程级隔离、资源限制（CPU/Memory/Time） | 当前阶段 |
| Phase 3 | DockerSandbox | 容器级隔离、网络命名空间、只读文件系统 | 后续迭代 |

### 5.2 LocalSandbox（Phase 1）

- 使用独立进程执行用户代码。
- 资源限制：
  - CPU：最多 2 核
  - 内存：最高 512MB
  - 超时：最长 30 秒
- 文件系统：挂载只读工作区 + 临时写入目录
- 网络：默认禁止出站连接

### 5.3 DockerSandbox（Phase 3）

- 每个 Task 启动独立的临时容器。
- 容器特性：
  - 只读根文件系统
  - 网络命名空间隔离
  - cgroup v2 资源限制
  - 容器生命周期 = Task 生命周期
- 镜像管理：预构建最小化镜像，定期安全扫描

## 6. 凭证管理

### 6.1 存储策略

- 所有敏感凭证（API Key、Token、密码）使用 AES-256 加密存储。
- 加密密钥不与凭证存储在同一位置。
- 运行时凭证仅驻留内存，不落盘。

### 6.2 最小权限原则

| 凭证类型 | 权限范围 | 有效期 |
|----------|----------|--------|
| API Key | 仅限指定服务、指定 scope | 按需轮换 |
| Token | 单次 Task 内有效 | Task 结束自动销毁 |
| 数据库密码 | 仅限本地 SQLite | 静态存储 |

### 6.3 凭证泄露响应

1. 自动撤销所有相关凭证
2. 生成新的加密密钥对
3. 记录安全审计事件
4. 通知受影响的用户

## 7. 网络安全

### 7.1 HTTPS

- 所有对外通信强制使用 TLS 1.3。
- 证书自动续期（Let's Encrypt / 内部 CA）。
- 禁用弱加密套件与旧版协议（SSLv3、TLS 1.0/1.1）。

### 7.2 CORS 策略

```nginx
Access-Control-Allow-Origin: https://nanamigopher.example.com
Access-Control-Allow-Methods: GET, POST
Access-Control-Allow-Headers: Authorization, Content-Type
Access-Control-Max-Age: 3600
```

- 生产环境不允许 `*` 通配符。
- 开发环境可通过配置临时放宽。

### 7.3 CSP（内容安全策略）

```
Content-Security-Policy: default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: https:; connect-src 'self' https://api.nanamigopher.example.com;
```

- 禁止内联脚本执行（除必要的 `unsafe-inline` 样式外）。
- 限制可连接的远程域名白名单。
- 禁止 frame 嵌入（防止点击劫持）。
