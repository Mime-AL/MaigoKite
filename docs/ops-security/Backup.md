# NanamiGopher 备份与恢复

> **状态**：Current
> **最后核验**：2026-09-14
> **权威范围**：备份范围、一致性、加密、恢复和演练

## 1. 备份优先级

| 数据 | 优先级 | 说明 |
|---|---|---|
| 关系数据库 | 核心 | Workspace、消息、任务、审批和Memory事实 |
| 原始文档内容 | 核心 | 向量索引的重建来源 |
| Workspace/用户配置 | 重要 | 不含Secret值 |
| Skill用户配置与Grant | 重要 | Skill包可按hash重新获取时无需重复保存 |
| 向量/FTS索引 | 可选 | 可重建，按恢复时间目标决定是否备份 |
| 日志与审计 | 按合规要求 | 与业务备份采用独立保留策略 |

Secret Provider中的密钥和业务备份分开管理。

## 2. 一致性

- SQLite使用 backup API 或经过checkpoint的一致性快照，不直接复制活动数据库文件。
- PostgreSQL使用受支持的逻辑/物理备份和时间点恢复。
- 对象/内容存储备份与数据库快照记录共同的 backup ID。
- 备份清单记录架构、Schema、应用、索引和密钥版本。

## 3. 加密流程

```text
一致性快照
→ 生成manifest与内容hash
→ 压缩
→ 使用随机nonce的认证加密
→ 保存外部校验和与密钥版本
```

不得先加密再压缩。生产密钥由Keychain/Vault/KMS管理，不把解密密钥与备份存放在一起。

## 4. 保留策略

保留策略按部署和风险配置，不在架构文档写死数量。至少定义：

- 快照频率。
- 本地与异地副本。
- 保留周期和不可变窗口。
- RPO/RTO。
- 删除与合规例外。
- 密钥轮换后的历史恢复能力。

## 5. 恢复

```text
选择备份
→ 验证manifest、hash和密钥版本
→ 解密与解压
→ 恢复到隔离环境
→ 执行Schema兼容检查
→ 验证Workspace、消息、任务、审批和文档
→ 重建或验证派生索引
→ 切换服务
→ 观察和记录结果
```

恢复不得直接覆盖仍在写入的生产目录。发生不兼容时停止切换，保留原环境。

## 6. 演练

- 自动备份验证不能替代定期完整恢复演练。
- 桌面SQLite和服务器PostgreSQL分别演练。
- 检查任务/审批终态、外键、文档hash和索引重建。
- 演练报告记录实际RPO/RTO、失败项、负责人和修复期限。

## 7. 验收

- [ ] 数据库和原始文档均在备份范围。
- [ ] Secret密钥与备份分离。
- [ ] 压缩发生在加密之前。
- [ ] SQLite备份具有一致性保证。
- [ ] 可以从权威数据重建索引。
- [ ] 最近一次恢复演练满足目标。
