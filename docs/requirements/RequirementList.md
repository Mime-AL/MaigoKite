# MaigoKite 需求与验收

> 状态：当前有效（产品要求，不表示功能均已交付）。
> 范围：个人智能体的用户目标、约束与验收。交付顺序和证据只在 [交付路线与状态](../project/Roadmap.md) 维护。

## 1. 产品范围与优先级

产品面向单一自然人。工作区组织个人项目和资料，多个获准设备访问同一个执行主机。保留既有工作区/成员关系数据兼容，不建设团队管理或多租户平台。

- P0：通用执行闭环及发布阻塞项。
- P1：个人日常使用、运行可靠性与手机远程访问。
- P2：有需求证据的个人工作流和扩展。
- P3：数据可携带性、扩展分发和原生系统集成。

领域案例不能直接决定内核。能由技能/MCP 完成的能力默认放在扩展层；涉及跨领域权限、恢复或执行一致性的能力才进入核心。

## 2. 核心需求

### R-CORE-01 模型与对话

用户能配置云端或本地模型，选择默认模型，并在会话中覆盖选择。

- 保存多个聊天连接；会话可选择模型、响应档位和权限模式。
- 基础地址不得重复追加 `/v1`；兼容调用必须命中正确端点。
- 公开过程、工具调用和最终回答分别展示。
- 敏感凭证只进入凭证存储和核心服务进程内存。

验收：至少一个实际端点完成目录发现、连接验证和真实对话；默认与会话选择保持一致。连接规则见 [模型接入](../agent-capabilities/models/model-routing.md)。

### R-CORE-02 工具编排

用户描述目标后，智能体能连续使用工具，无需用户在应用间反复复制信息。

- 单个任务可提出一个或多个工具调用。
- 工具经过参数校验、ToolPolicy、执行、结果回注和审计。
- 工具失败提供稳定错误码、用户提示和可选设置入口。
- 原始调用 JSON 不得混入最终回答气泡。
- 审批暂停后保留完整待执行意图，不重复已完成副作用；具体恢复依据由所用运行时决定。

验收场景：连续调用多个工具；工具失败后模型解释或选择替代；同轮多个受保护调用逐项审批且不丢失调用。实现范围见 [智能体运行时设计](../design/AgentRuntime.md)。

### R-CORE-03 浏览器操作

用户能完成需要页面交互的任务，而不只是获取网页文本。

- 支持 open、snapshot、fill、click、press、screenshot 和 close。
- 只允许公开 HTTP(S) 目标，拒绝 URL 凭证及 loopback/private/link-local/reserved 地址。
- screenshot 只能写入工作区。
- 风险按动作和参数判断，需批准的动作暂停并展示实际目标。
- 不绕过验证码、站点访问控制或平台的自动化限制。

验收场景：打开页面、读取快照、按策略批准交互、将截图写入受控路径并关闭会话；公开站点、登录态与下载上传的验证范围分别记录。

### R-CORE-04 持续任务与取消

用户切换会话或离开页面后，任务仍有独立生命周期，并可显式停止。

- 发消息返回任务 ID，任务不依赖原始 HTTP 请求存活。
- 不同会话独立运行，不共享全局发送锁。
- 任务有运行、等待审批和明确终态。
- 取消关闭 pending 审批与活动工具调用；结束确认不能先于实际运行清理。
- 同步线程或第三方调用不能立即中止时，必须如实显示限制，不承诺强制抢占。

验收场景：切页后返回、模型流式输出中取消、工具执行中取消、核心服务关闭；取消后不得产生新的执行输出。不同运行时的现状见 [智能体运行时设计](../design/AgentRuntime.md)。

### R-CORE-05 权限批准

用户只需理解三种执行模式，并能判断具体操作是否允许。

- 模式为 read_only、workspace、full_access。
- 风险、路径范围、allowlist 和 hard-deny 由 ToolPolicy 内部维护。
- 审批绑定主体、任务、工具调用、参数摘要值、版本和过期时间。
- 网关和 UI 不能绕过核心服务最终授权。
- 参数或范围变化使旧审批失效；决定只消费一次。

验收场景：允许、拒绝、过期、重复决定、版本冲突、参数变化和支持路径的进程重启。完整规则只在 [工具权限](../agent-capabilities/security/tool-permission.md) 定义。

### R-CORE-06 状态恢复

用户重新进入对话后能知道任务完成、失败、待批准还是中断。

- 会话、消息、任务、工具调用、审批和产品事件持久化。
- 事件有稳定 ID 和会话内递增 sequence，客户端去重并检测缺口。
- 普通断线不取消任务；重新连接补拉历史并恢复投影。
- 核心服务重启后的续跑仅适用于所用运行时和工具已验证支持的状态；其他任务标记 interrupted。
- “恢复真实状态”不等于“任意步骤自动续跑”，提交去重也不等于工具副作用恰好一次（exactly-once）。

验收场景：关闭/重开数据库；等待文件审批时真正重启核心服务；超单页历史、补拉时新增事件；文件副作用后的 crash/replay。恢复机制见 [智能体运行时设计](../design/AgentRuntime.md)，传输契约见 [API 设计](../design/API.md)。

### R-CORE-07 技能与 MCP 扩展

用户能添加流程知识或外部工具，而不修改内核。

- 从配置目录发现 `SKILL.md`，校验元数据、大小与目录边界。
- 声明式 instruction/workflow 内容按需 list/read，不直接执行包内代码或扩大权限。
- 部署配置启动受信 stdio MCP Server，工具进入统一权限和审计链路。
- UI 只展示实际加载结果，不能用空安装按钮假装支持包管理。

验收场景：新增合法/非法/重复技能；stdio MCP 启动、发现、调用和关闭；清单与实际运行一致。技能与 MCP 分别遵守各自接入规范，不建立新的插件框架。

### R-CORE-08 客户端与工作区

用户能查看回复和活动、处理审批、停止任务，以及检查工作区文件结果。

- Web/Electron 提供模型、权限选择、活动时间线与审批入口。
- 文件树、文本预览和 Git 差异只读，服务端限制路径和大小。
- 重新进入会话查询服务端状态，不依赖 WebSocket 内存。
- 助手显示称呼按用户偏好保存，不修改项目名或工作区名。
- 最终回答、简短过程、工具活动分开展示，不暴露隐藏思维链。

验收：Vue 类型检查、组件/状态仓库测试和构建；另行验证真实桌面启动、关闭和打包。交互规则见 [前端与桌面交互设计](../design/FrontendDesign.md)。

## 3. 手机远程需求

### R-PERSONAL-REMOTE-01 手机远程入口（规划中）

同一用户通过已配对手机向电脑智能体发起任务、查看进度、处理审批、停止任务和阅读结果。手机断线不取消主机任务，重连恢复同一会话；手机不运行另一套运行时。

首版边界、连接选择、排除项及 R0–R3 验收统一在 [手机远程访问](../design/RemoteAccess.md) 维护。它不是团队部署，也不以记忆或工作流为前置条件。

## 5. 非功能约束

- 本地服务默认监听 loopback；远程入口必须认证。个人定位不取消路径、设备、凭证和主体边界。
- URL、文件、命令和 MCP 环境实施边界校验；外部内容不能提升权限。
- 敏感凭证不进入普通配置、日志、产品事件、记忆或业务数据库。
- 产品状态和事件应一致提交；尚未达到的部分登记为债务，不因此预设必须自研 Outbox/事件溯源。
- 依赖故障给出明确状态；不静默降级到其他付费或远程服务。
- 前端按会话隔离更新，长列表避免全量重绘；浏览器按需启动并回收。
- 事件历史有响应上限并需分页；性能结果注明模型、硬件、规模、并发与版本。
