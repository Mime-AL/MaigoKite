### UC-001: 创建新对话

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-001 |
| **用例名称** | 创建新对话 |
| **参与者** | 用户、管理员 |
| **前置条件** | 用户已登录系统，应用已启动 |
| **基本流程** | 1. 用户在左侧导航栏点击"新建对话"按钮<br>2. 系统创建一个新的空对话实例<br>3. 系统为新对话分配唯一 ID 并初始化空记忆<br>4. 新对话出现在左侧导航栏顶部<br>5. 中间工作区显示欢迎界面和快捷指令建议 |
| **备选流程** | 2a. 用户从快捷指令中选择预设模板（如"代码审查"、"文献摘要"）<br>  → 系统根据模板预填充初始 System Prompt 和工具集<br>2b. 用户通过快捷键 Ctrl+N 创建新对话<br>  → 系统执行与步骤 1-5 相同的逻辑 |
| **后置条件** | 系统中存在一个可用的新对话实例，等待用户输入 |
| **业务规则** | BR-001: 每个用户最多同时拥有 50 个活跃对话<br>BR-002: 新对话默认使用上次对话的权限模式<br>BR-003: 对话名称可由用户自定义，默认使用第一条消息的前 30 个字符 |

### UC-002: 发送消息并获得回复

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-002 |
| **用例名称** | 发送消息并获得回复 |
| **参与者** | 用户 |
| **前置条件** | 用户已选中一个活跃的对话实例 |
| **基本流程** | 1. 用户在输入框中键入消息<br>2. 用户点击"发送"按钮或按 Enter 键<br>3. 系统将消息发送到 Agent Core<br>4. Agent Core 加载对话上下文和记忆信息<br>5. Agent Core 调用 LLM 生成回复<br>6. 系统以流式方式逐字展示回复内容<br>7. 回复完成后，对话历史记录保存该轮交互 |
| **备选流程** | 5a. LLM 生成过程中用户点击"停止"按钮<br>  → 系统中止当前生成，保留已输出内容<br>  → 下一条用户消息将开启新的对话轮次<br>5b. LLM 调用超时（> 60 秒）<br>  → 系统显示超时错误提示<br>  → 用户可选择重试或更换模型<br>5c. 系统检测到需要调用工具<br>  → 系统进入 UC-003 工具调用流程<br>  → 工具执行完毕后继续生成回复 |
| **后置条件** | 对话记录新增一轮用户消息和 AI 回复 |
| **业务规则** | BR-004: 单条消息最大长度 10,000 字符<br>BR-005: 回复内容超过 5,000 字符时自动折叠，用户可展开<br>BR-006: 流式响应延迟阈值 200ms，超过则显示缓冲动画 |

### UC-003: 执行工具调用

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-003 |
| **用例名称** | 执行工具调用 |
| **参与者** | 用户、Agent Core |
| **前置条件** | 1. 用户已发送消息且 Agent Core 判断需要调用工具<br>2. 工具权限等级与当前对话的权限模式兼容 |
| **基本流程** | 1. Agent Core 生成工具调用请求，包含工具名和参数<br>2. 权限管理器检查当前工具的权限等级（L1-L5）<br>3. 根据权限模式决定执行策略：<br>  - **Manual**: 弹出确认对话框，用户点击"允许"后执行<br>  - **AcceptEdits**: 自动允许文件编辑类工具（L1-L2），其他需确认<br>  - **Plan**: 先展示执行计划，用户确认后批量执行<br>  - **Auto**: 所有 L1-L3 工具直接执行，L4-L5 仍需确认<br>4. MCP 适配器将请求转发给对应的原子工具<br>5. 工具执行并将结果返回给 Agent Core<br>6. Agent Core 将结果整合到回复中展示给用户 |
| **备选流程** | 3a. 权限检查未通过<br>  → 系统拒绝执行，向用户展示拒绝原因<br>  → Agent Core 尝试用其他方式完成任务或告知用户限制<br>4a. 工具执行失败（文件不存在、命令语法错误等）<br>  → 系统捕获异常并格式化错误信息<br>  → Agent Core 根据错误信息重试或调整策略<br>4b. Bash 命令执行超时（> 120 秒）<br>  → 系统强制终止命令执行<br>  → 返回超时错误信息 |
| **后置条件** | 工具执行结果已记录到对话历史，系统状态恢复可接受新消息 |
| **业务规则** | BR-007: 每个对话每秒最多执行 10 次工具调用<br>BR-008: 单次会话最多连续执行 50 次工具调用，超出后需用户确认<br>BR-009: L5 级工具（如 rm -rf、sudo 等）在任何模式下都需显式确认<br>BR-010: 工具执行结果超过 10KB 时自动截断并提示 |

#### 工具权限等级矩阵

| 等级 | 危险程度 | 涉及工具 | 默认模式 |
|------|----------|----------|----------|
| L1 | 只读 | file_read, glob, grep, web_search | 自动允许 |
| L2 | 低风险写入 | file_write, todo_write | AcceptEdits 自动允许 |
| L3 | 中等风险 | bash (受限命令), web_fetch | 需确认 |
| L4 | 高风险 | bash (系统命令), sleep | Manual 必须确认 |
| L5 | 极高风险 | bash (破坏性命令) | 任何模式需显式确认 |

### UC-004: 管理 Skill

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-004 |
| **用例名称** | 管理 Skill（安装、卸载、更新） |
| **参与者** | 用户、开发者 |
| **前置条件** | 用户已登录并具有 Skill 管理权限 |
| **基本流程** | 1. 用户进入"Skill 管理"页面<br>2. 系统展示已安装的 Skill 列表，包含名称、版本、描述、作者<br>3. 用户选择一个 Skill 并点击"安装"<br>4. 系统读取 Skill 的 SKILL.md 文件，解析元数据和指令模板<br>5. 系统将 Skill 保存到本地 Skill 目录<br>6. 系统验证 Skill 的格式和安全性<br>7. Skill 安装成功后出现在对话快捷指令列表中 |
| **备选流程** | 3a. 用户从 Skill 市场浏览并安装<br>  → 用户在市场中选择 Skill，点击"安装到项目"<br>  → 系统执行与步骤 4-7 相同的逻辑<br>3b. Skill 安装验证失败<br>  → 系统显示验证错误详情<br>  → 用户可选择修复后重试或取消安装<br>4a. 用户更新已安装的 Skill<br>  → 系统检测新版本，提示用户确认更新<br>  → 更新后重新加载 SKILL.md<br>4b. 用户卸载 Skill<br>  → 系统从 Skill 目录移除文件<br>  → 清理相关的缓存和配置 |
| **后置条件** | Skill 列表已更新，新的 Skill 立即可用于对话中的快捷指令 |
| **业务规则** | BR-011: Skill 必须以 SKILL.md 文件形式存在<br>BR-012: Skill 命名遵循 `category/skill-name` 格式（如 `code/review`）<br>BR-013: 用户只能安装自己目录下的 Skill 或经信任列表认证的 Skill<br>BR-014: Skill 更新时保留用户的自定义配置 |

| **业务规则** | BR-018: 工作流节点最多支持 100 个<br>BR-019: 工作流执行需要的所有工具权限必须在执行前一次性授予<br>BR-020: 工作流定义支持版本管理，每次修改生成新版本号 |

### UC-009: 管理定时任务

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-009 |
| **用例名称** | 管理定时任务 |
| **参与者** | 用户 |
| **前置条件** | 用户已登录系统（Phase 4） |
| **基本流程** | 1. 用户进入"定时任务"页面<br>2. 用户点击"新建定时任务"<br>3. 系统展示任务配置表单：<br>  → 任务名称<br>  → 触发时间（单次/重复/Cron 表达式）<br>  → 执行内容（Prompt 模板）<br>  → 通知方式（站内消息/邮件/推送）<br>4. 用户填写配置并点击"保存"<br>5. 系统在后台注册定时任务<br>6. 到达触发时间时，系统自动执行任务并通知用户<br>7. 用户在任务列表中查看执行历史和结果 |
