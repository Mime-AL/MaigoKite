### UC-001: 创建新对话

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-001 |
| **用例名称** | 创建新对话 |
| **参与者** | 用户、管理员 |
| **前置条件** | 用户已登录系统，应用已启动 |
| **基本流程** | 1. 用户在左侧导航栏点击"新建对话"按钮<br>2. 系统创建一个新的空对话实例<br>3. 系统为新对话分配唯一 ID 并初始化空记忆<br>4. 新对话出现在左侧导航栏顶部<br>5. 中间工作区显示欢迎界面和快捷指令建议 |
| **备选流程** | 2a. 用户从快捷指令中选择预设模板（如"代码审查"、"文献摘要"）<br>  → 系统根据模板预填充初始 System Prompt 和工具集<br>2b. 用户通过快捷键 Ctrl+N 创建新对话<br>  → 系统执行与步骤 1-5 相同的逻辑 |
| **后置条件** | 系统中存在一个可用的新对话实例，等待用户输入 |
| **业务规则** | BR-001: 每个用户最多同时拥有 50 个活跃对话<br>BR-002: 新对话默认使用上次对话的权限模式<br>BR-003: 对话名称可由用户自定义，默认使用第一条消息的前 30 个字符 |

### UC-002: 发送消息并获得回复

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-002 |
| **用例名称** | 发送消息并获得回复 |
| **参与者** | 用户 |
| **前置条件** | 用户已选中一个活跃的对话实例 |
| **基本流程** | 1. 用户在输入框中键入消息<br>2. 用户点击"发送"按钮或按 Enter 键<br>3. 系统将消息发送到 Agent Core<br>4. Agent Core 加载对话上下文和记忆信息<br>5. Agent Core 调用 LLM 生成回复<br>6. 系统以流式方式逐字展示回复内容<br>7. 回复完成后，对话历史记录保存该轮交互 |
| **备选流程** | 5a. LLM 生成过程中用户点击"停止"按钮<br>  → 系统中止当前生成，保留已输出内容<br>  → 下一条用户消息将开启新的对话轮次<br>5b. LLM 调用超时（> 60 秒）<br>  → 系统显示超时错误提示<br>  → 用户可选择重试或更换模型<br>5c. 系统检测到需要调用工具<br>  → 系统进入 UC-003 工具调用流程<br>  → 工具执行完毕后继续生成回复 |
| **后置条件** | 对话记录新增一轮用户消息和 AI 回复 |
| **业务规则** | BR-004: 单条消息最大长度 10,000 字符<br>BR-005: 回复内容超过 5,000 字符时自动折叠，用户可展开<br>BR-006: 流式响应延迟阈值 200ms，超过则显示缓冲动画 |

### UC-003: 执行工具调用

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-003 |
| **用例名称** | 执行工具调用 |
| **参与者** | 用户、Agent Core |
| **前置条件** | 1. 用户已发送消息且 Agent Core 判断需要调用工具<br>2. 工具权限等级与当前对话的权限模式兼容 |
| **基本流程** | 1. Agent Core 生成工具调用请求，包含工具能力、参数和资源范围<br>2. ToolRegistry 将其解析为 Native Tool 或 MCP Tool<br>3. ToolPolicy 按当前模式、有效授权和规范化参数决定允许、审批或拒绝；完整规则引用工具权限规范<br>4. 需要审批时挂起 Task，由用户查看副作用预览并决定<br>5. 获准后由对应 Native Tool 或 MCPClient 执行<br>6. Agent Core 保存 ToolCall 结果并继续任务 |
| **备选流程** | 3a. 权限检查未通过<br>  → 系统拒绝执行，向用户展示拒绝原因<br>  → Agent Core 尝试用其他方式完成任务或告知用户限制<br>4a. 工具执行失败（文件不存在、命令语法错误等）<br>  → 系统捕获异常并格式化错误信息<br>  → Agent Core 根据错误信息重试或调整策略<br>4b. Bash 命令执行超时（> 120 秒）<br>  → 系统强制终止命令执行<br>  → 返回超时错误信息 |
| **后置条件** | 工具执行结果已记录到对话历史，系统状态恢复可接受新消息 |
| **业务规则** | BR-007: 工具调用受部署侧速率与并发策略约束<br>BR-008: 长执行链达到配置阈值后暂停并请求用户继续<br>BR-009: L5 操作需逐次确认；命中 hard-deny（如破坏系统根路径）时始终拒绝<br>BR-010: 大结果通过引用或分页返回，阈值由部署配置决定 |

#### 工具权限规则

权限等级和模式矩阵以 [工具权限规范](../agent-capabilities/security/tool-permission.md) 为唯一来源；用例不维护第二份工具映射。

### UC-004: 管理 Skill

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-004 |
| **用例名称** | 管理 Skill（安装、卸载、更新） |
| **参与者** | 用户、开发者 |
| **前置条件** | 用户已登录并具有 Skill 管理权限 |
| **基本流程** | 1. 用户进入 Skill 管理页<br>2. 选择本地导入或注册源安装<br>3. 系统获取内容并计算 hash<br>4. 验证 `SKILL.md`、来源、依赖和静态安全<br>5. 展示能力、资源与凭证请求<br>6. 用户或管理员批准<br>7. 系统创建不可变 SkillVersion 与 Workspace SkillGrant，并按 kind 激活 |
| **备选流程** | 验证失败时不创建活动 Grant；更新扩大能力时重新审批；卸载前停止新调用并检查依赖关系。完整流程见 [Skill 生命周期](../agent-capabilities/skills/skill-lifecycle.md)。 |
| **后置条件** | Skill 版本与 Workspace Grant 已持久化，运行状态可独立查看和禁用。 |
| **业务规则** | Skill Manifest、导入、安装、授权、更新和卸载规则只由 [Skill 生命周期](../agent-capabilities/skills/skill-lifecycle.md) 定义。 |

### UC-005: 查看和执行检查器（Inspector）

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-005 |
| **用例名称** | 查看和执行检查器（Inspector） |
| **参与者** | 用户、开发者、运维人员 |
| **前置条件** | 当前有一个活跃的对话正在进行工具调用 |
| **基本流程** | 1. 用户在右侧面板切换到"Inspector"标签<br>2. 系统展示当前对话的工具调用链视图<br>3. 每条调用记录显示：工具名、参数、状态（待执行/执行中/已完成/失败）、耗时<br>4. 用户点击某条调用记录可查看详细信息（完整参数、返回内容、错误堆栈）<>5. 系统高亮显示当前正在执行的工具调用<br>6. 用户可通过 Inspector 面板暂停或恢复执行 |
| **备选流程** | 4a. 用户想查看历史对话的工具调用链<br>  → 用户在 Inspector 中选择"历史记录"模式<br>  → 系统加载该对话的完整 Trace 信息<br>4b. 用户想导出 Trace 数据用于调试<br>  → 用户点击"导出 Trace"<br>  → 系统生成 JSON 格式的 Trace 文件供下载 |
| **后置条件** | 用户获得了对话执行过程的可视化洞察 |
| **业务规则** | BR-015: Inspector 默认在右侧面板展示，可通过拖拽调整宽度<br>BR-016: 工具调用链深度超过 20 层时自动折叠<br>BR-017: 敏感信息（API Key、密码等）在 Inspector 中自动脱敏显示 |

| **备选流程** | 3a. 用户从模板市场选择预设工作流<br>  → 系统加载模板内容到编辑器<br>  → 用户修改参数后保存执行<br>4a. DSL 语法验证失败<br>  → 系统高亮错误位置并显示错误说明<br>  → 用户修复后重新验证<br>6a. 工作流执行过程中某个节点失败<br>  → 系统暂停执行并显示失败详情<br>  → 用户可选择重试该节点、跳过或终止整个工作流<br>6b. 工作流执行超时（> 300 秒）<br>  → 系统自动终止并保存部分结果 |
| **后置条件** | 工作流执行结果已保存，用户可查看执行报告和日志 |
| **业务规则** | BR-018: 节点和运行上限由部署策略配置<br>BR-019: 每次工具调用仍经 ToolPolicy 判定，不能靠工作流预授权绕过动态风险<br>BR-020: 工作流定义版本不可变，修改产生新版本 |

### UC-007: 配置模型和权限

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-007 |
| **用例名称** | 配置模型和权限 |

### UC-010: 查看每日回顾

| 字段 | 说明 |
|------|------|
| **用例编号** | UC-010 |
| **用例名称** | 查看每日回顾 |
| **参与者** | 用户 |
| **前置条件** | 用户在前一日有活跃的对话记录（Phase 4） |
| **基本流程** | 1. 系统每天早晨 8:00 自动生成前一日的回顾报告<br>2. 回顾报告包含：<br>  → 昨日对话总数和总消息数<br>  → 工具调用统计（按类型分类）<br>  → 使用的模型和 Skill 列表<br>  → 重点对话摘要（Top 3）<br>  → 今日建议（基于历史使用模式）<br>3. 用户在通知中心或首页看到回顾提示<br>4. 用户点击查看详情<br>5. 系统展示完整的每日回顾页面<br>6. 用户可选择分享或导出回顾报告 |
| **备选流程** | 3a. 用户前一天没有活跃对话<br>  → 系统跳过生成回顾，不发送通知<br>3b. 用户想查看历史回顾<br>  → 用户在回顾页面选择日期<br>  → 系统加载对应日期的回顾记录 |
| **后置条件** | 用户获得了前一日的使用情况总结和洞察 |
| **业务规则** | BR-031: 每日回顾仅使用本地数据，不涉及云端上传<br>BR-032: 用户可在设置中关闭每日回顾功能<br>BR-033: 回顾报告保留最近 30 天 |

```
                    ┌─────────────────┐
                    │   UC-002 发送    │

                    └────────┬────────┘
                             │
              ┌──────────────┼──────────────┐
              │              │              │
        ┌─────▼─────┐ ┌─────▼─────┐ ┌──────▼──────┐
        │ UC-003    │ │ UC-005    │ │ UC-006      │
        │ 工具调用   │ │ Inspector │ │ 工作流执行   │
        └───────────┘ └───────────┘ └─────────────┘
              │              │              │
              └──────────────┼──────────────┘
                             │
                    ┌────────▼────────┐
                    │   UC-001 创建    │
                    │   新对话         │
                    └─────────────────┘

关联关系：
  ● UC-001 → UC-002: 必须先创建对话才能发送消息
  ● UC-002 → UC-003: 消息回复可能需要工具调用
  ● UC-002 → UC-005: 对话执行过程可通过 Inspector 监控
  ● UC-002 → UC-006: 复杂任务可通过工作流编排执行
  ● UC-004 → UC-006: 工作流依赖已安装的 Skill
  ● UC-007 → UC-002: 模型和权限配置影响消息回复行为
  ● UC-008 → UC-001: 历史搜索可回溯已创建的对话
  ● UC-009 → UC-006: 定时任务本质是自动触发的 Mini 工作流
  ● UC-010 → UC-008: 每日回顾基于历史对话数据统计生成
```
