# NanamiGopher 用户故事

> 状态：Current。故事围绕通用执行内核组织；领域示例不是独立产品方向。

## Phase 1：必须满足

| ID | 用户故事 | 验收重点 |
|---|---|---|
| US-01 | 作为用户，我希望描述一个目标后由 Agent 连续使用多个工具，以便减少在应用间复制粘贴。 | 多 ToolCall、结果回注、最终回复分离 |
| US-02 | 作为用户，我希望 Agent 能操作浏览器，而不只是抓取网页文本，以便处理需要页面交互的任务。 | 会话化 open/snapshot/fill/click/press；动作审计 |
| US-03 | 作为用户，我希望风险操作先显示它将作用于什么资源，以便决定允许或拒绝。 | 三档模式、动态风险、版本化审批 |
| US-04 | 作为用户，我希望切换对话或暂时离开后任务仍保持自己的状态，以便并行处理工作。 | 按会话独立运行任务，不使用全局发送锁 |
| US-05 | 作为用户，我希望重新进入对话时看到真实进度，以便知道任务完成、失败、等待批准还是因重启中断。 | 任务/审批/事件历史恢复与去重 |
| US-06 | 作为用户，我希望能立即停止运行任务，以便控制时间、费用和副作用。 | 停止按钮、取消 API、Approval/ToolCall 一致转换 |
| US-07 | 作为用户，我希望失败时看到下一步可做什么，而不是只看到原始 JSON。 | 稳定错误码、用户提示、设置入口 |
| US-08 | 作为 Owner，我希望配置云端或本地兼容模型并选择默认项，以便自行控制模型和数据位置。 | 模型发现、验证、Base URL 规范化、Secret 隔离 |
| US-09 | 作为扩展作者，我希望用 SKILL.md 给 Agent 添加可审阅的流程知识，以便不用修改 Core。 | Local Skill 发现、校验、list/read、不执行任意代码 |
| US-10 | 作为扩展作者，我希望通过 MCP 暴露外部工具，以便复用相同权限和审计机制。 | stdio 发现、namespace、统一 ToolPolicy |
| US-11 | 作为用户，我希望看到 Agent 的简短过程和工具状态，但不把它们混进回复框。 | reasoning/tool 活动流与 message 分离 |
| US-12 | 作为用户，我希望设置助手显示称呼，以便界面符合个人偏好。 | 用户级持久化，不修改项目/Workspace 名称 |

## 领域需求准入

生图、电子开发、自动化、业余无线电或招聘只是候选工作流。一个候选进入实施前必须回答：

1. 是否存在高频、重复、跨工具的真实任务；
2. 浏览器/Skill/MCP/Workflow 能否完成，是否真的需要改内核；
3. 错误副作用与人工接管点是什么；
4. 有多少目标用户愿意持续使用或付出配置成本；
5. 是否能用小型试验衡量节省时间或提高成功率。

未通过准入的功能保留为研究样例，不进入核心路线图。
