## 1. 用户故事格式说明

每条用户故事遵循标准格式：

```
作为 [角色]，我希望 [行为/功能]，以便 [价值/目的]。
```

### 优先级体系（MoSCoW）

| 级别 | 含义 | 符号 |
|------|------|------|
| **Must have** | 必须有，否则产品不可用 | M |
| **Should have** | 应该有，严重影响体验但不阻塞核心流程 | S |
| **Could have** | 可以有，锦上添花的功能 | C |
| **Won't have** | 本版本不做，放入 backlog | W |

### 故事标签

| 标签 | 含义 |
|------|------|
| `P0` | Phase 1 必须实现 |
| `P1` | Phase 1 可延后 |
| `P2` | Phase 2 实现 |
| `P3` | Phase 3 实现 |
| `P4` | Phase 4 实现 |

## 3. 按 Phase 分组的用户故事

### 3.1 Phase 1（Week 1-2）— Framework MVP

**目标：建立对话+工具+记忆+权限的核心闭环，交付 2 个 Example。**

#### P0 核心故事

| ID | 标题 | 描述 | MoSCoW | 验收标准 |
|----|------|------|--------|----------|
| US-P1-001 | 发起对话 | 用户打开应用后能与 AI 发起一轮对话 | M | 1) 应用启动后显示欢迎页；2) 用户输入消息后 AI 返回回复；3) 回复内容以流式方式展示 |
| US-P1-002 | 文件读取工具 | AI 能通过 file_read 工具读取用户指定的文件内容 | M | 1) 用户要求 AI 读取某文件时，AI 调用 file_read；2) 文件内容正确返回并在对话中展示；3) 不支持的文件类型给出友好提示 |
| US-P1-003 | 文件写入工具 | AI 能通过 file_write 工具创建或覆盖文件 | M | 1) 用户要求 AI 写入内容到文件时，AI 调用 file_write；2) 文件内容正确写入磁盘；3) 只读档位下写入前需用户确认 |
| US-P1-004 | Bash 命令执行 | AI 能通过 bash 工具在沙箱中执行命令 | M | 1) 用户授权后 AI 可执行 bash 命令；2) 命令输出正确返回；3) 危险命令触发 L4/L5 权限拦截 |
| US-P1-005 | 待办事项管理 | AI 能通过 todo_write 工具管理待办列表 | M | 1) 用户要求添加待办时 AI 正确记录；2) 用户要求标记完成时 AI 正确更新状态；3) 待办列表在对话中可查询 |
| US-P1-006 | 权限风险系统 | 系统按 L1-L5、参数与资源范围判断工具风险 | M | 1) 风险等级由 ToolPolicy 内部维护；2) 不同风险对应不同审批流程；3) 参数变化会重新判定 |
| US-P1-007 | 记忆系统 | AI 能在对话中记住上下文信息 | M | 1) 同一对话内多轮上下文正确传递；2) 用户偏好信息被持久化；3) 跨对话的记忆隔离 |
| US-P1-008 | 权限模式切换 | 用户能在只读/工作区/完全访问三种档位间切换 | M | 1) 设置界面提供 3 种档位；2) 调用按档位、风险、授权范围共同判定；3) L5 与 hard-deny 不因完全访问而绕过 |
| US-P1-009 | Web 搜索工具 | AI 能通过 web_search 工具搜索互联网 | S | 1) 用户要求搜索时 AI 调用 web_search；2) 搜索结果以结构化方式展示；3) 支持中英文混合搜索 |
| US-P1-010 | 2 个 Example | 提供 2 个可运行的示例场景 | M | 1) Example 1: 代码审查流程完整可运行；2) Example 2: 文档摘要流程完整可运行；3) 每个 Example 有清晰的使用说明 |
| US-P1-014 | 模型接入设置 | 用户能为 Workspace 配置一个可实际调用的 Chat 模型 | M | 1) 支持 OpenAI/Anthropic API；2) 支持 Ollama 与 OpenAI-compatible 本地端口；3) 可从 Base URL 获取模型目录；4) 可测试连接并立即应用；5) Secret 不进入普通配置和数据库 |
| US-P1-015 | 界面助手称呼 | 用户能设置界面中的助手称呼 | S | 1) 称呼按 Workspace 用户持久化；2) 会话、欢迎页和输入框统一显示；3) 不修改项目名或 Workspace 名 |

| ID | 标题 | 描述 | MoSCoW | 验收标准 |
|----|------|------|--------|----------|
| US-P2-001 | 多对话管理 | 用户能同时创建和管理多个独立对话 | M | 1) 左侧导航栏显示对话列表；2) 新建对话不影响已有对话；3) 对话间记忆隔离 |
| US-P2-002 | 可恢复流式响应 | 用户在断线或切换页面后仍能恢复 AI 的增量输出 | M | 1) 事件按序列去重和补缺；2) 流式过程中用户可随时中断；3) 中断后新消息开启新轮次 |

| US-P2-004 | 高级模型管理 | 用户能发现并按会话选择多个本地或云端模型 | S | 1) 自动发现本地模型；2) 会话可选择模型；3) fallback 时通知用户 |

| US-P2-007 | OCR 文字识别 | 用户能上传图片让 AI 识别其中的文字 | S | 1) 拖拽或粘贴图片即可触发 OCR；2) 识别结果以文本形式展示；3) 支持中英文混合识别 |
| US-P2-008 | 对话搜索 | 用户能搜索历史对话内容 | S | 1) 搜索框支持关键词匹配；2) 结果按相关性排序；3) 支持按日期范围筛选 |
